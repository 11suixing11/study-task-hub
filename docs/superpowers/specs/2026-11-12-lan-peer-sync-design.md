# 学习任务聚合平台改进计划：局域网对等同步

日期：2026-11-12

基线：`main`，提交 `4a10b16`，Windows / Android 1.1.2

状态：设计评审版。本文给出改进范围、技术方向、实施阶段和验收标准；尚未实施代码变更。

## 1. 已确认的方向

用户已明确选择：

1. 本轮优先新增功能与跨设备同步。
2. 仅通过同一局域网交换数据，不使用云端。
3. 采用对等同步，任意两台设备均可互相同步，不指定 Windows 为固定协调端。

因此需要覆盖 Windows↔Android、Android↔Android、Windows↔Windows。每台设备继续使用自己的本地数据库；断网后仍能查看、修改任务，下次连接再交换变化。

本文建议首版服务于同一使用者的多台设备。陌生用户之间的共享任务、跨局域网中继和公共协作不纳入首版。

## 2. 三种路线与选择依据

| 路线 | 优点 | 代价 | 本轮决定 |
| --- | --- | --- | --- |
| 对等设备交换增量操作 | 任意两台可以同步；手机之间无需电脑；支持离线后合并 | 需要处理多端冲突、操作去重、删除传播和移动端监听 | 按用户选择采用 |
| Windows 提供固定同步入口 | 实现和排错较简单 | 手机之间依赖电脑应用运行 | 不采用 |
| 文件导出与导入 | 容易制作备份，网络要求低 | 手动操作多，难以持续合并多端修改 | 可作为后续备份功能，不替代同步 |

## 3. 首期功能范围

### 3.1 同步的数据

- 手动任务与已采集任务。
- 人工维护的标题、课程名、备注、完成/忽略/被打回等状态、开始和截止时间、进度、成绩、优先级，以及人工修改标记。
- 采集任务的平台来源、任务身份、官方原始状态、时间依据和必要的课程归属。
- 经校验的任务跳转链接，通过受信任的加密连接传输，接收后用本机保护机制重新加密。
- 明确删除与恢复操作、用于合并的版本信息。

首版不跨设备传输平台 Cookie、账号密码、登录票据、WebView profile、原始页面正文或通知发送历史。平台登录仍由本人分别在各设备完成。通知开关、自动采集开关、课程采集范围先作为各设备的本地设置保留。

远端任务不能因为本机尚未登录或未选课程而无提示地消失。首页增加“来自其他设备”的来源标识和查看入口；是否由本机继续自动采集，仍按本机登录与选课决定。不能确认任务归属时保留独立来源，不凭课程名或标题合并。

### 3.2 用户能操作的入口

- 设置中的“设备与同步”页：开启局域网同步、发现设备、配对、立即同步、查看上次结果、取消配对。
- 首版提供一次性配对码和两端核对确认；二维码配对作为便利入口，在移动端扫描能力验证后加入同一流程。
- 已配对设备在双方应用可通信时自动交换增量，同时保留“立即同步”按钮。
- 同步状态明确区分：发现中、等待对方确认、传输中、已完成、对方离线、连接中断、存在冲突。
- 首次合并前显示任务数量与数据范围，并创建本机备份。
- 同字段的并发人工修改进入冲突列表，可查看两个值及来源设备，选定后同步解决结果。

### 3.3 首版运行边界

- 双方处于可以互通的同一局域网；访客网络或路由器设备隔离可能阻止通信。
- Windows 应用运行期间可在托盘维持同步；Android 首版以应用前台可通信为交付要求。
- 手机被系统休眠、回收进程或离开局域网后保留未同步变化，回到应用时重连。持续后台监听另行评估前台服务、通知与耗电，不承诺首版一直在线。
- 自动发现失败时提供手动地址与配对信息输入。该入口可应对发现报文被过滤，但不能绕过路由器的设备隔离。
- 目标兼容现有 Windows 10 1809+ x64 与 Android 9+；实际网络与加密能力在阶段 0 验证。

## 5. 建议架构

### 5.1 共享模块与平台接入

新增独立的 `src/AccessProbe.Sync/` 共享 C# 模块，负责同步 DTO、操作日志协议、身份和配对、差异交换、合并规则与同步会话。模块不引用 WPF、Android UI 或任何平台登录窗口，也不直接依赖现有 TaskItem 类型，避免将目前两端按源码共享的领域类型重复装入新程序集。

通过 `src/AccessProbe/TaskStore.Sync.cs` 将 TaskItem 转换为同步数据，并接入数据库事务。两端分别提供网络生命周期、界面调度和本机密钥保护适配器。既有平台解析器和官方登录流程不整体重写。

传输首选共享 .NET TCP 与 TLS 流；设备发现采用局域网广播，手动连接作为兜底。阶段 0 验证 Android↔Android 的监听、TLS 身份校验、网络切换和系统生命周期后固定实现。若共享 TLS 监听在目标 Android 环境无法成立，先返回验证结果调整传输适配层，不改回固定电脑协调端。

### 5.2 设备身份与配对

- 每台安装实例拥有持久化 DeviceId 和身份密钥。
- 初次配对需要一次性凭据和两端确认；配对码过期、重复使用、错误次数过多均拒绝。
- 配对时核对握手派生校验信息或二维码中的身份指纹；不能静默接受任意自签名证书。
- 配对后固定对方身份，后续连接校验身份变化；新地址不能替代身份验证。
- 首次启用创建本地同步组。另一台设备明确加入该组后才合并数据；不同已有同步组不能静默混合。
- 第三台设备加入同一组后，允许已授权的成员转送变化，但保留原始操作身份。取消配对先在当前设备生效；现有任务保留。首版不宣称一次本地取消会在离线设备上即时撤销授权。
- 同步默认关闭，由用户开启；发现报文只包含临时发现标识、协议版本与连接端口，不广播任务、课程或平台登录状态。

### 5.3 增量交换与间接传递

每个操作以 `(originDeviceId, sequence)` 唯一标识。sequence 与操作日志在同一数据库事务中递增并持久化。操作携带任务同步身份、字段变化、因果上下文、来源类别和删除/恢复信息。

设备互相交换“各来源设备连续收到的操作序号”，补发缺少的操作。存在序号缺口时不能提前确认后面的连续水位。收到的批次校验、落库与接收水位更新在同一事务完成，提交后才确认；重复批次按操作身份忽略。

三台设备的目标行为为：A 修改任务并与 B 同步，随后 B 与 C 同步，即使 A 当时离线，C 仍能收到 A 的修改。转发保留 A 的操作身份，防止同步回环产生重复变化。首次配对已有数据时建立基线并交换身份映射；后续才按日志补齐。

默认批次目标为最多 100 个操作且消息不超过 1 MiB；超限拆批，单条非法数据拒绝并说明原因。中途断开从已提交水位继续，不把“开始发送”记成成功。

### 5.4 任务身份与合并

- 手动任务以原始创建 GUID 作为跨设备身份；两个分别创建的同名任务保持独立。
- 已采集任务以同步组、平台和已验证 SourceKey 匹配；账号或课程归属不确定时保留独立身份。
- 本机 TaskItem.Id 可以保留，使用同步身份映射处理两台设备独立采集同一任务时产生的不同本地 GUID。
- 本地 Revision 继续用于当前数据库编辑校验；跨设备另用因果版本，不能把设备时间或本地 Revision 当作全局顺序。
- 不同字段的离线人工修改可以合并；同字段的并发人工修改保留双方候选并进入待处理列表。
- 冲突时，有可确定共同基线则保留该值；没有共同基线则使用确定性候选作为暂时显示值，并明确标记未解决。选择结果生成同时覆盖两方版本的新操作，所有设备按相同规则收敛。
- 人工覆盖继续优先于采集结果。并发的官方状态或截止时间冲突保留来源与依据，不能仅按手机/电脑时钟判定正确值；未确认日期仍遵循现有可信截止规则。
- 平台读取失败、部分分页、某次没有返回任务都不能产生跨设备删除。

### 5.5 删除、恢复与提醒

明确删除产生 tombstone，并与本机删除任务一起提交。所有平台导入路径检查 tombstone，避免下一次自动采集立即复活已删除任务。首版保留删除标记，不自动清理尚可能被离线设备引用的记录。

删除与离线编辑并发时，默认隐藏任务并保留编辑候选，进入冲突页；只有明确恢复操作才重新显示。单纯收到一条旧任务数据不能恢复删除记录。

远端变化应用后重算本机提醒。首次合并已有任务不批量发出“新任务”通知；后续远端新增提醒由本机独立开关决定。某端标记完成后，其他端已排但未发的提醒应取消；操作系统已发出的历史通知不作为任务状态依据。

数据库恢复不能复用一个已经回退的操作序号。备份恢复流程生成新的安装身份，重新配对/导入同步基线，保留已有操作来源信息与 tombstone。

## 6. 分阶段实施路线

估算以 1 名开发者、有可用 Windows 环境和两台 Android 真机为前提。合计约 17–28 个有效开发日，约 4–6 周；阶段 0 之后再调整排期，不作为交付日期承诺。

### 阶段 0：环境与对等通信可行性，2–3 日

- [ ] 准备 .NET 10、现有 Windows 与 Android 构建环境，按项目脚本建立隔离数据基线。
- [ ] 在两台 Android 设备之间验证双向连接、TLS 握手与身份校验；另验证 Windows↔Android。
- [ ] 验证自动发现与手动地址连接、双方同时发起连接、网络断开、切换 Wi-Fi、退到后台与返回。
- [ ] 固定首版监听生命周期、发现策略、消息上限和前台使用说明，记录实测数据。

**出口标准：** Android↔Android 在没有电脑参与时完成经过身份校验的双向传输；失联后能恢复；Windows↔Android 同样成立。任一关键能力未成立时，先调整传输方案再推进。

### 阶段 1：离线合并与存储基础，5–8 日

- [ ] 建立共享同步模型、设备序号、任务身份映射、操作日志、接收水位、冲突记录和 tombstone。
- [ ] 数据库增加版本迁移与升级前备份；旧版程序遇到新版库给出明确提示，不尝试修改新库。
- [ ] 将本地新增、编辑、状态变更、删除和各平台导入接入同一事务化变化记录。
- [ ] 在多个隔离数据库中验证首次合并、幂等补发、字段合并、并发冲突、删除/恢复和第三台转发。
- [ ] 检查所有来源的任务身份和人工覆盖规则，确保跨端修改不被平台采集覆盖。

**出口标准：** 不依赖真实网络，三副本在操作乱序、重复与离线编辑场景下收敛；删除不被旧设备和采集复活；不存在已确认但未持久化的操作。

### 阶段 2：配对与实际增量同步，4–7 日

- [ ] 接入局域网发现、手动连接、一次性配对确认、设备信任与取消配对。
- [ ] 接入受信任连接、协议版本协商、分批传输、超时取消、断线续传和失败记录。
- [ ] 处理双方同时连接的重复会话：按设备身份确定保留方向，避免两条会话重复发送。
- [ ] 验证不认识的设备、错误配对码、身份变化、不同同步组、坏数据和超大消息均被拒绝。
- [ ] 对已配对设备实现应用可通信时自动增量交换，且保留明确的手动同步动作。

**出口标准：** 三种设备组合完成首次合并与后续增量同步；未配对设备不能读取数据；断线恢复无重复任务、无丢失变更。

### 阶段 3：两端用户流程与冲突处理，3–5 日

- [ ] 增加“设备与同步”页面、首次合并预览、上次成功时间和本次同步摘要。
- [ ] 增加远端任务来源标识，区分平台采集结果与设备交换结果。
- [ ] 提供冲突详情、保留候选、选定值和明确恢复删除任务的操作。
- [ ] 明确本机未登录/未选课时的远端任务展示，以及本机继续采集的入口。
- [ ] 提供每台设备的提醒开关；首次合并静默，完成状态传播后撤销待发提醒。
- [ ] 完成配对码流程；在扫码可行性已验证时追加二维码便利入口。

**出口标准：** 用户能从设备页完成发现、配对、同步、断线恢复、解决冲突和取消配对；任务从何而来、是否同步成功、哪里需要处理都能看见。

### 阶段 4：真机与交付验收，3–5 日

- [ ] 验证三台设备轮流相遇，以及 Android↔Android 独立同步。
- [ ] 验证自动采集、人工编辑与设备同步同时进行；检查课程归属、链接、覆盖标记和提醒。
- [ ] 验证 Android 生命周期、通知权限、局域网发现失败兜底和 Windows 防火墙提示。
- [ ] 验证现有 1.1.2 数据升级、首次合并备份、恢复身份重建、取消配对后重新配对。
- [ ] 直接使用最终 Windows 包和 Android APK 进行验收，报告绑定同一批最终文件哈希。
- [ ] 更新 README、安装说明、设备同步说明和发布验证摘要。

**出口标准：** 下述验收矩阵通过，并由实际 Windows 和两台 Android 设备证明三种设备组合可用；模拟器与单元检查不能替代这些网络与生命周期结论。

| R14 | 5,000 个任务与 100 个增量变化 | 记录首次耗时、增量耗时、传输量及内存；普通局域网增量目标 5 秒内，不含发现和人工配对 | 0、2、4 |

## 9. 同步交付后的新功能候选

1. **课程选择跨端复用：** 在平台账号归属可确认时传递选课建议；本机确认后才开始自动采集，避免远端设置静默扩张范围。
2. **提醒中心：** 显示各设备的提醒设置和待提醒任务，允许选择常用提醒设备。长期后台能力先经系统约束与耗电验证。
3. **本地备份与恢复：** 提供版本化备份、恢复预览和同步身份重建，避免恢复旧库导致删除任务复活或操作序号回退。
4. **周视图与筛选收藏：** 在统一任务数据稳定后增加按周查看截止任务、保存常用筛选的入口。

这些候选不作为首版对等同步的发布前置条件。先交付可靠的任意两端数据交换，再按实际使用收益选择下一项。

## 10. 实施与评审方式

本文先评审首期数据范围、前台运行边界与冲突体验。确认设计后，以阶段 0 的实测结果固定传输细节，再使用 writing-plans 拆成包含具体接口、测试、文件变更和提交边界的执行计划。

代码实施时使用隔离工作区、针对同步行为的 TDD、模块评审与最终验证。测试使用独立数据库、密钥和本地响应；正式任务库及官方登录环境不作为测试夹具。

PTA 已知登录保存问题和现有最终包真机验收缺口作为并行维护项保留。局域网任务同步不复用登录归档，不能被描述为解决了官网票据过期或 PTA 保存竞争。
