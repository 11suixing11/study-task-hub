# Windows 傻瓜化接入与任务首页设计

日期：2026-11-17
范围：Windows WPF 客户端第一版体验优化

## 目标

让第一次使用 Windows 客户端的用户不需要理解“同步服务、会话、诊断、课程目录”等内部概念，就能完成以下主路径：

1. 打开软件后先看到任务首页，而不是被登录窗口拦住。
2. 看到哪些平台尚未接入，并知道接入后会得到什么。
3. 点击一个平台后，在同一个应用窗口完成官方登录。
4. 登录完成后自动检查账号、读取课程；需要用户选择时只做一次课程确认。
5. 同步结束后自动回到任务首页，看到任务数量和最近截止项。
6. 某个平台登录失败时能留在当前上下文中重试，不影响其他平台和已保存任务。

第一版只优化 Windows 的页面结构、文案、状态呈现和导航衔接；保留现有官方登录、WebView2、课程选择、同步、任务入库及官方任务跳转实现。

## 用户路径

### 首次启动

主窗口直接打开任务首页。首页顶部显示“连接平台后，作业、考试和截止时间会自动汇总到这里”，并提供主按钮“开始接入”。已有任务时不显示阻塞式引导，只在首页顶部显示轻量同步提示。

### 接入中心

点击“开始接入”后进入应用内接入中心。接入中心由平台卡片组成，每张卡只显示：平台名称、用途描述、当前状态、最近同步时间和一个主动作。状态统一为：

- 未接入：`连接平台`
- 登录中：`正在等待官方登录`
- 需要确认课程：`确认课程`
- 同步中：`正在同步`
- 已同步：`已同步 N 条任务`
- 需要重试：`重新连接`

平台卡片不显示诊断码、Cookie、响应类别和内部服务名。高级诊断仍保留在连接页的折叠区域。

### 登录页

连接页左侧只保留一个清晰的步骤面板，右侧保留官方 WebView。步骤固定为：

1. 在右侧完成官方登录。
2. 等待应用自动确认登录。
3. 如果出现课程选择，只勾选本人正在学习的课程。
4. 返回任务首页查看汇总结果。

页面状态使用“当前正在做什么 + 用户下一步能做什么”的句式。自动检查继续运行；手动按钮只在页面需要用户介入时出现，主要按钮文字为“重新打开登录页”“刷新登录页”“确认课程并同步”。

登录状态必须区分：页面加载失败、登录未确认、账号已确认但课程读取失败、课程为空、课程选择保存失败和任务同步未完成。每种状态最多给出一个主动作和一个次要动作。

### 成功返回

当账号确认、登录保存和课程/任务读取满足现有平台成功条件时，连接页显示简短结果：`已连接 · X 门课程 · Y 条任务`，并自动返回任务首页。首页顶部显示本次同步结果，并保留“查看平台”入口。

如果官网返回空课程或覆盖不完整，不自动伪装成成功：留在连接上下文，解释“已登录，但暂时没有读到可用课程”或“已读取部分课程，仍需核对”，提供“重试读取”和“返回首页”两个动作；已保存任务继续可用。

## 页面与视觉结构

### 任务首页

沿用现有三栏任务工作区：左侧分类/平台，中间任务列表，右侧任务详情。第一版调整信息层级：

- 顶部增加一条可关闭的接入摘要条，未连接时显示主行动“开始接入”；已连接但正在同步时显示进度；发生平台错误时显示“查看需要处理的平台”。
- 统计区域只突出“待完成”“即将截止”“已逾期”三个用户决策指标。
- 平台侧栏把连接状态放在平台名称旁，使用文字和颜色同时表达，不依赖颜色单独传达含义。
- 空状态按原因区分：没有接入平台、已接入但正在读取、已接入且当前筛选没有任务。
- 搜索、筛选和高级平台同步详情保留，但默认不抢占主操作区域。

### 接入中心

接入中心使用统一卡片网格或垂直卡片列表，优先展示支持且最可能使用的平台。每个卡片高度一致，状态、主按钮位置一致，避免用户逐个平台重新学习。

### 连接页

连接页使用“左侧步骤/状态 + 右侧官方页面”的布局。左侧状态面板固定在可见区域，说明区域和高级诊断分离。浏览器错误不使用系统 MessageBox 打断；错误直接显示在状态面板，并提供恢复按钮。

### 视觉规范

继续使用现有 FluentTheme.xaml 作为主题入口：浅灰白画布、白色表面、克制蓝色主按钮、红/琥珀/绿色仅表达真实状态。统一卡片圆角、内边距、标题和辅助文字层级；不添加虚构平台图标或装饰性动画。主按钮每个页面最多一个，其他动作使用次级按钮或文本按钮。

## 技术边界

- 保留现有同步服务、平台解析器、会话保存、WebView2 profile 和任务数据库。
- 不新增账号密码收集，不代替用户登录、答题或提交。
- 不把浏览器已经打开、Cookie 存在或二维码出现直接当作登录成功；继续以现有官网验证结果为准。
- 不改变正式数据目录；所有自动化检查使用独立合成数据或已有测试数据目录。
- 不把高级诊断从代码中删除，只降低普通用户默认看到的复杂度。
- 不改变 Android。

## 组件边界

### ConnectionSummaryBar

输入：平台状态摘要、任务计数、是否有待处理错误。

输出：显示摘要、触发“开始接入”“查看平台”“重试平台”等事件。

职责：只做首页接入引导和结果提示，不执行登录和同步。

### PlatformAccessCard

输入：平台名称、描述、状态、最近同步信息。

输出：触发指定平台的连接或查看事件。

职责：用统一结构呈现平台状态；不直接调用同步服务。

### ConnectionFeedback

现有 `ConnectionFeedback` 继续作为状态事实到用户文案的转换层。第一版扩展或调整标题、步骤、解释和下一步文本，使连接页与接入中心使用同一套状态含义；不让 XAML 自己猜测错误原因。

### Workspace navigation

沿用现有 `TaskDashboardWindow` 的单窗口路由。接入中心和连接页作为工作区页面打开，返回操作恢复任务首页；成功流程通过已有导航事件回首页，旧页面结果不能覆盖新页面。

## 错误恢复原则

- 页面加载失败：给“重新打开登录页”。
- 登录未确认：给“刷新登录页”，保留已打开的官方页面。
- 登录已确认但课程读取失败：给“重试读取课程”。
- 课程为空：说明官网当前没有可用课程，给“刷新课程列表”和“返回首页”。
- 保存课程失败：保留勾选状态，给“再次保存并同步”。
- 同步部分完成：显示已保存数量和未完成原因，给“重试同步”；不清空已有任务。
- WebView2/环境失败：给“重新初始化连接页”，同时显示简短环境提示；详细诊断留在高级区域。

所有错误文案遵循三段式：发生了什么、对当前结果有什么影响、现在可以做什么。

## 验收标准

### 首次使用

- 启动后可直接看到任务首页。
- 未连接时能在一个明显位置找到“开始接入”。
- 从接入中心到平台连接页不产生第二个独立主窗口。
- 用户不需要先理解高级诊断字段才能完成登录。

### 登录

- 登录页显示固定三步说明，并能自动检查登录状态。
- 页面加载失败、登录未确认、课程为空、课程读取失败和同步部分完成显示不同结果。
- 每种失败状态至少有一个可执行恢复动作，且不使用模糊的“请重试”。
- 登录成功并满足现有完整条件后自动回到首页。

### 首页

- 首页能区分未接入、正在同步、已连接无任务和筛选后无结果。
- 平台状态与首页摘要使用一致的中文状态。
- 任务列表、筛选、详情和官方入口的现有功能继续可用。
- 窗口默认尺寸、最小尺寸和窄窗口布局不出现横向溢出。

### 回归

- 现有 ProbeChecks、TaskDashboardHarness 和平台连接布局检查继续通过。
- 新增首页接入摘要、接入中心卡片和连接状态文案的行为检查。
- 构建 Windows 项目零警告、零错误。
- 预览和自动化验证使用独立数据，不写入正式任务库、Cookie 或 profile。

## 第一版实现顺序

1. 把接入中心与首页摘要的状态模型接入现有 `TaskDashboardWindow`。
2. 将平台连接入口统一到接入中心，并保持已有单窗口导航。
3. 优化各类连接页的左侧步骤与状态文案，统一主按钮和失败恢复动作。
4. 调整首页空状态、同步摘要、平台状态和视觉间距。
5. 增加行为检查、布局检查和完整 Windows 构建验证。

## 暂不纳入第一版

- 自动代填账号密码。
- 跨设备账号或任务同步。
- 后台无感登录或绕过官方验证。
- 重新设计平台采集器和解析器。
- Android UI。
- 复杂首次运行教程、营销动画和多层设置向导。
