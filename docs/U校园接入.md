# 旧版 U 校园接入

已按用户确认的 `https://u.unipus.cn/index.html/` 接入旧版 U 校园官方登录、班课目录、作业、测试和普通课件单元采集。限时单元按未完成必学项的最早截止时间参与首页优先级排序。任务汇入统一清单，参与来源统计、课程选择、状态与截止日期展示和提醒；不生成每日学习计划。FiF 按要求停止适配，保留手动任务和历史数据。

2026-11-03 起，从左侧打开 U 校园平台管理，点击“连接平台”完成官方登录；确认后保存最新 Cookie，并先返回全部已适配班课目录。勾选课程并点击“保存选择并采集”后，才读取已选班课的全部状态作业、测试。新安装及旧配置迁移均需确认范围，新增班课需要再次勾选。“刷新课程列表”只更新目录，保留最近的任务同步结果；取消课程选择会停止该课采集与提醒，历史任务仍保留。

平台管理集中提供连接、刷新、选择、同步、停止与自动开关，支持缩放和收起课程区，没有多用户选项。最新 Cookie 用 DPAPI 当前用户加密保存到任务库 `platform_sessions` 表，旧 `.local/sessions/ucampus.bin` 兼容迁移。启动和连接默认复用有效 Cookie，保留官方有效期，不额外设置 30 天期限。短期会话失效先通过官方 TGC 单点登录续期，再复核同一账号；辅助 Cookie 变化不再误判换号。失效标记阻止直接激活会话，但保留密文仅供官方复核；明确清除登录数据才永久移除凭据。续期写回共享 WebView 和加密仓库，网络故障不清登录。连接窗口关闭立即保存新登录，未完成账号复核时保持“已保存、待确认”。

旧登录入口先跳至 `/t?p=...`，再由脚本进入 `sso.unipus.cn/sso/login`；项目允许这条官方链路。账号检查使用 `/user/data/getToken` 的 `openId` 与适用的 `ucamUserId` Cookie 核对；接口返回的 token 不用于生成 JWT 或套用新版 UAI 的认证方式。登录、同步使用同一独立 WebView2 环境和 DPAPI 会话归档，续期、失效、重连及重启恢复均已接入。

## 采集范围

| 数据 | 已确认的旧版契约 | 限制 |
| --- | --- | --- |
| 班课目录 | `/user/student/index` 中正式课程卡片的隐藏入口与名称 | 排除宣传卡片；登录页、未知空白页不作为零课程 |
| 课程归属 | `/user/student/mycourse/courseCatalog` 的数据库课号、班级和作业/测试入口 | 课件 ID 独立保存，不混用数据库课号，不自动加入班级 |
| 作业 | `/user/student/homework/index` 页面中的 type=1 列表参数 | 普通个人作业入口可解析；小组和互评入口待核对 |
| 测试 | 同一列表页面的 type=2 分支，带班级与 eccId 参数 | 测试独立记录，与同编号作业保持身份隔离 |
| 课件单元 | `ucontent.unipus.cn/course/api/` 的课件信息、目录、课程进度和单元进度 | 仅普通 type=0 结构；type=3/5 等特殊课件明确报告未适配 |
| 分页 | `/user/student/homework/list` 的 totalRow、pageNumber、totalPage 和 pageSize | 每页 10 条、页号从 1 开始；每类最多 100 页，单轮最多 600 次请求 |

列表请求不筛选提交状态；作业与测试分别读完后才标记该课完整覆盖。每个列表全部分页确认后才导入本列表数据，重复页、跨页重叠、总数变化、未知结构、失效或上限均报告未完整读取，不能判成没有任务。正式库内的历史任务和手动修改保留。

## 状态、日期与入口

官网 `state=0` 归入待办、`state=-1` 归入被打回；`state=2` 且不是互评时归入完成。其他状态和互评完成待核对。`newState` 的“已结束”“进行中”“未提交”单独保留，“已结束”不会直接推断为完成。

普通开放和截止日期按官网中国文本时间解析；互评场景仅在官网标明提交截止时采用 `peer_evaluation_start_time`，仅有互评截止时保留提交截止未知。普通课件的单元必学进度已覆盖，特殊课件及其他学习活动仍须核对，作业列表零条不说明课程没有其他任务。

### 单元截止与必学进度

目录、课件信息和课程进度的发布版本必须一致，账号、课件、单元和学习节点逐项绑定。按目录递归识别章节及 group/link 终点，仅采用终点 `strategies.required` 判断必学；单元汇总状态不替代具体必学状态。`pass=1` 为完成，`pass=0/2` 未完成，`pass2` 不替代完成证据。目录展示类型与进度类型分别识别，不能因为未访问节点返回 `text` 就丢弃官网目录中的 check/discussion/task 节点。

单元、章节和终点的开放时间取交集（开始取最大、截止取最小），日期按 Unix 秒读取。首页采用未完成必学项的最早有效截止，已完成节点的旧截止不会占据待办优先级。全部必学完成显示 100% 和已完成；没有必学显示已忽略并保留单元日期。明确 null 才表示不限时；缺字段、未知状态、毫秒或矛盾时间保留待核对。未知必学进度清空旧自动百分比，手动进度与手动状态继续优先。

单元与作业、测试独立计算覆盖，课件失败仍可采集作业和测试，保留单元历史。同步详情分别展示学习单元、限时单元、必学未完成单元数量及单元覆盖情况。单元入口保留官方课程目录与本地归属标记，点击后只复核账号、课程归属、目录和进度，再打开具体未完成节点的官网路由；后台不读取学习正文或答案、不自动加入班级。

普通个人作业、测试保存按账号、课程、班级、任务和类型校验的入口；点击时才通过 `/user/student/homework/chk` 或 `examDetail` 获取临时签名，再使用系统浏览器打开官方页面。签名不保存到任务库；后台不下载题目和作答正文、不提交、不自动确认重做。官网要求重做确认或返回的类型不匹配时停止打开并提示。系统浏览器可能仍需官网登录，真实最终页面尚待用户验收。

## 故障

2026-11-04 的历史 `UC002` 排查发现 `/user/data/getToken` 经 HTTP 302 转入官方 SSO。当时版本识别跳转后要求重新登录，见 [历史诊断](../artifacts/releases/20261104-141231-e33d6dad/verification/platform-errors-readonly-checks.json)。2026-11-07 已改为使用现有 TGC 沿确认的官方 GET 链路续期，固定本站回跳并限制白名单、最多 8 跳，成功后必须复核同一账号。课程接口报未登录时先复核账号并同账号重试一次；课程权限不足、账号复核不可用与真正账号失效分别处理，旧响应不能覆盖新登录。

已修复学生页在异步会话确认前弹窗被拦截后留下的红色登录失败提示。本次官方学生页已加载且账号、课程读取确认后，清除当前弹窗错误并保留历史事件；连接窗口提前关闭也会完成诊断恢复。只停留在登录页或会话未确认时仍保留错误；主导航、内嵌验证页、资源、证书和浏览器故障不会被后续弹窗或后台成功掩盖。

| 错误码 | 处理 |
| --- | --- |
| UC001 | 官方复核及续期后仍明确失效，在连接窗口重新登录；任务和受保护的复核凭据保留 |
| UC002 | 网络或读取未完成，查看同步详情后重试 |
| UC003 | 会话、结构或归属未确认，核对官方页面 |
| UC004 | 会话保存或清理失败，检查项目目录权限 |
| UC005 | 限流、重复分页或读取上限，本轮任务覆盖未确认 |
