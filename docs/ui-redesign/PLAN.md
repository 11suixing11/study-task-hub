# 聚合平台 · Stageshow 界面重构

目标：按用户本次要求，先显示可直接操作的 Stageshow Windows 界面预览，再把相同布局落实到 Windows 应用。完整保留登录、课程选择、定向同步、状态和官方任务入口。

- 媒介：可操作的 React + Stageshow 预览、Windows 原生应用。本轮不改 Android。
- 起点：复制项目内 `static-card` gold 的 Stage、Window、Row、Card、Button、Badge 与文字层级，先拍摄 gold，再改学习任务内容与布局。
- 焦点：左侧平台导航，中间统一任务清单，右侧当前任务详情；统计突出待办与最近截止，Windows 默认保留全部状态，平台管理按需打开。
- 外观：灰白背景、深灰文字、蓝色主操作，红／琥珀／绿仅表达真实状态；12 px 基准间距，无虚构平台徽标。
- 桌面：约 1200 × 760 的完整操作界面，窗口填满舞台；用户要看到并操作界面，因此不采用会裁掉控件的营销硬裁切。任务列表可滚动，选中后详情与操作保持可见。
- 窄屏预览：358 px 独立布局，保留待办统计、搜索筛选和任务列表；任务详情打开为独立视图，不缩小三栏桌面。
- 预览交互：状态筛选、关键词搜索、平台切换、任务详情、完成／撤销、课程选择及同步演示；演示数据在预览宿主标明，不冒充已连接的真实账户。默认静态完整界面，状态变化使用轻量过渡，不强制播放占用用户操作的光标动画。
- 不修改账号、Cookie、采集接口及正式任务数据；验证用独立合成数据。
- 验收：默认静态预览的桌面／390／358 px still gate、真实点击和键盘操作、宿主布局、TypeScript 和构建；动画影片 gate 单独记录覆盖与结论。Windows 常规／最小尺寸、平台弹窗、现有业务与桌面回归。结果和待确认范围见 [REHEARSAL.md](REHEARSAL.md)。

采用 realistic 中文文本，灰白表面与克制蓝色，平台用文字名称，不虚构图标。所有开发与验证继续使用隔离数据。用户当前要求的可见预览通过本地浏览器打开，并提供再次启动的入口。
