# 登录账号后自动采集

已实现学习通、雨课堂与长江雨课堂的登录后自动采集，三个平台均已通过当前账号采集核对。打开首页后检查学习通及已连接平台的会话，登录后自动发现课程、读取任务并保存，每 30 分钟同步，无需逐个进入课程或点击保存。首页默认将全部平台和全部状态显示在一张“统一任务清单”，总数、来源数量及统计卡均覆盖全平台；手动录入任务也汇总到这里。“查看全部任务”清除搜索和筛选，“同步所有平台”刷新已接入平台并恢复统一视图。平台连接与同步、所选任务详情默认折叠，错误会展开平台详情。本文说明学习通链路；两个新平台见 [雨课堂接入](雨课堂接入.md)。

登录窗口和后台会话共用同一 WebView2 environment 和项目 profile。后台只发送适用于目标官方地址的 Cookie，不读取普通浏览器或保存账号密码。登录页面有导航时触发检查；没有主页面导航时，连接窗口打开期间每 5 秒检查登录会话。上一轮同步尚未结束时，登录后的检查会排队执行。清除登录数据时停止同步，重新登录后自动恢复。

学习通 Cookie 快照用 Windows DPAPI CurrentUser 加密写入 `.local/sessions/chaoxing.bin`。启动时在首次请求前恢复缺失且未过期的 Cookie，保持 domain/path、Secure、HttpOnly、SameSite、平台有效期与 session 属性；当前 profile 的同名同域同路径 Cookie 值发生变化时，整个旧归档不参与恢复。归档距保存超过 30 天、损坏或未知格式时不恢复，不延长平台有效期。登录后导航、关闭连接窗口、同步及退出前保存当前状态；退出先取消并等待后台同步，再保存与释放 WebView。

HTTP 读取从当前 profile 构造每次请求的 Cookie。官方响应的 `Set-Cookie` 续期与删除写回共享 CookieManager 和加密归档，下一轮新建 reader 继续使用更新值。读前及响应后检查会话代次和内存指纹；新登录、Cookie 变化、清除或退出期间返回的旧响应不写回，也不记录为新会话失败。指纹只在内存用于比较，不进入报告。官方明确判定失效时删除归档，本轮退出不重新保存该失效会话；网络错误、403 和未知结构不作为注销。用户“清除登录数据”等待旧请求结束，并清除归档和 profile，保留任务。

旧版已经丢失的临时 Cookie 不能重建，首次切换仍提示 `SYNC001` 时需完成一次官方登录。此修复的跨进程重启合成验证已通过，真实账号使用新发布完整退出后的验收仍待用户切换。平台注销、撤销和到期仍需官方登录。

## 请求链路

1. GET `https://i.chaoxing.com/base`，从页面读取唯一 fid；缺失或互相冲突时停止，不猜学校或账号参数。
2. GET `https://mooc2-ans.chaoxing.com/mooc2-ans/visit/courselistdata`，读取页面提供的课程入口和课程名。
3. GET 页面提供的 `/visit/stucoursemiddle` 课程入口；已适配平台 302 到 `mooc2-ans.chaoxing.com/mooc2-ans/mycourse/stu` 的跳转。课程、班级与 cpi 必须保持一致，直接使用平台返回的地址读取 workEnc、enc、openc。
4. GET `/mooc2/work/list`，使用 workEnc 作为作业列表签名，逐条读取名称、平台状态、时间原文和具体任务地址。
5. 按课程/班级/cpi/work ID 去重保存；使用页面给出的 `/mooc-ans/mooc2/work/task` 详情地址读取作答时间原文，自动同步平台明确状态并保留手动状态和编辑。已适配到 `/work/view` 与 `/work/prompt` 的跳转，继续请求前校验同一课程、班级、cpi、work ID 与已知 answer ID；原任务链接保持列表返回的签名地址。
6. 平台转入 `/work/dowork` 作答流程时，在请求该页面前停止，记录“详情转入作答页面”，列表任务仍保留。提交提示页只提供“提交时间”时，记录“平台未提供作答时间”，不把提交时间当作截止日期。

请求链路参考公开项目的 Web 请求契约并独立实现：[Xuexitong-mcp client.py](https://github.com/DanMo661/Xuexitong-mcp/blob/main/xuexitong_mcp/client.py)。公开实现不能替代本人账号对页面、完整性和签名的验证；不使用参考项目的登录自动化、参数兜底或作业操作。

## 完整性与限制

已识别的课程和作业分页链接自动跟随。未知分页、页面结构、课程权限、登录失效和读取上限会显示错误码，不作为空课程或空作业处理。单轮最多 200 门课程、每列表 20 页、100 条详情、600 次请求；列表每次更新，详情 24 小时内缓存。

完成、提交、待批阅和已批阅等明确标签归入完成；未交、待提交、进行中等归入待办，被打回和需重做归入被打回。未知或互相冲突的状态不猜测。用户手动操作后状态覆盖位保留，包括恢复未完成；旧版已有的非默认状态在迁移时保留。

作答区间按北京时间（UTC+8）转换；完整年份属于平台完整日期，缺少年份选择与采集时间相近的合理年份并标注“年份推定”。列表仅提供“剩余…小时…分钟”等时，用该列表响应的读取时间换算并标注“约”。推定和估算均参与优先级、逾期和临期筛选，定时提醒须手动核对确认。旧任务启动时迁移，不需要重新导入；缓存作答区间不在重复同步时滚动年份，详情保存也不会把旧倒计时从当前时刻重新计时。平台没有提供可用时间时保留未知。

明确的空作业页支持 `.task-list .has-content > .null-data` 中的“暂无作业”；存在作业行时不按空页处理。详情的提交提示与作答流程分别计入 `DetailsUnavailable`、`DetailsRequireAction`，可在“同步详情”查看本轮数量。这两类结果保留列表元数据，其他未知结构继续报 `SYNC006`。

诊断只保存数量、结果、错误码和读取边界；任务链接由 Windows DPAPI 当前用户保护。`scripts/read-sync-status.py` 分别输出三个平台的连接、覆盖、任务状态和日期计数；其余五个平台尚未自动适配。

## 点击任务直达

首页任务名称为可点击入口，选中任务也可点击“做题 / 提交”；完成任务按钮显示“查看作业”。依据 PRD，页面在系统浏览器打开。点击时重新读取正式库中的最新签名链接，使用项目采集会话对 `/work/task` 发出 GET，仅检查响应头。平台返回同一任务的 `/work/dowork`、`/work/prompt` 或 `/work/view` 后，将原地址交给系统浏览器；不在聚合平台内请求这些目标页面或读取作答正文。HTTP 官方跳转先改用 HTTPS，保留原路径和参数。未知跳转或课程/班级/cpi/work/已知 answer ID 不一致时停止并提示 `LINK003`。

同一任务入口的签名刷新允许最多 6 次响应头请求，并检测重复跳转。平台未跳转时直接打开该任务入口。采集会话失效、网络失败或限流时仍可打开已保存任务入口，由系统浏览器的官方页面处理登录；不会把 Cookie 复制到浏览器。手动录入或用户更换的链接直接打开。打开过程中链接被同步或用户修改时重新读取，任务被删除时停止；点击不修改完成状态、截止时间或提交作业。
