## Windows 安装和旧记录

先在旧版首页点击“退出程序”，再双击 EXE，按中文安装向导操作。右上角 × 只隐藏到托盘。安装版已包含 .NET 运行环境，不需要安装开发 SDK 或 Python；首次缺少 WebView2 时向导会安装 Microsoft 官方运行时。EXE 当前没有发布者签名，Windows 可能显示“未知发布者”。

首次安装可以选择“导入这台电脑上的旧版聚合平台记录”，选择包含 `.local/data/tasks.db` 的旧项目文件夹，例如 `C:\Users\yuki\Desktop\聚合平台`。导入只复制 SQLite 记录和旧版加密会话归档，保留源文件；浏览器 profile 不复制。已有安装版任务库时，升级继续使用已有记录，不覆盖成旧库。

从桌面或开始菜单“聚合平台”启动。安装程序与任务数据分开保存：

| 内容 | 默认位置 |
| --- | --- |
| 程序 | `%LOCALAPPDATA%\Programs\LearningTaskAggregator` |
| 任务、选课与加密 Cookie | `%LOCALAPPDATA%\LearningTaskAggregator\.local` |
| 原项目记录 | 原项目的 `.local`，导入后仍保留 |

升级前退出程序，重新运行新安装包。Windows 卸载只移除程序，保留外部数据；同一 Windows 用户重新安装后继续使用。Cookie 和任务入口使用当前 Windows 用户加密，不能直接拷贝到其他用户或手机使用。若官网已过期，在相应平台重新登录即可，已有任务保留。

## Windows 便携版

将 ZIP 完整解压到可写文件夹，打开“聚合平台-1.1.2-便携版-win-x64”目录，再双击“启动聚合平台.cmd”。其中 `app` 目录包含正式程序、.NET 运行环境与第三方许可，不要单独移动 EXE。

便携版省略安装流程，默认数据仍保存到 `%LOCALAPPDATA%\LearningTaskAggregator\.local`，与同一 Windows 用户的安装版共用。旧项目记录需通过安装向导选择导入；便携入口不会自动搬运旧项目。安装版或便携版切换前均需点击“退出程序”。缺少 Microsoft WebView2 时可运行安装程序，由向导安装官方运行时。

## Android 安装和使用

将“聚合平台-1.1.2-android.apk”传到手机，在文件管理器中打开，按手机提示允许该来源安装应用。安装完成后打开“聚合平台”；若需要截止提醒，允许通知权限。APK 包含 arm64-v8a、armeabi-v7a 和 x86_64 三种架构及自己的运行环境。沿用旧版签名，可直接覆盖更新；桌面交付目录中附有“Android-1.1.2-使用说明.txt”、版本专用验证报告、第三方许可和 SHA256 校验文件。

1. 首页找到课程所在的平台，点击“管理平台”，再点击“连接平台”。支持扫码辅助的平台点击“官网扫码登录”，等待二维码显示；学堂在线先点击官网右上角“登录”。
2. 点击“保存并打开”对应 App。学习通、旧版 U 校园与智慧树打开学习通、U 校园学生版与知到，雨课堂、长江雨课堂与学堂在线打开微信。在官方 App 的扫一扫中选择相册，识别刚保存的二维码并确认。
3. 返回聚合平台，保持原连接页。官网确认后自动加密保存 Cookie 并读取课程目录；也可点击“登录完成并读取课程”。请等到“登录已保存”或课程目录加载完成再离开登录页。MOOC 完成官网登录后进入官网首页确认账号。
4. 勾选课程，点击“保存选择并采集”。确认选择前只读取目录，新增课程需再次勾选。平台管理可收起和展开课程区域。
5. 返回首页查看统一任务清单，打开任务查看状态、截止与来源。官方入口通过手机浏览器打开，浏览器有自己的登录状态，可能要求再次登录或核验。
6. 可添加手动任务，选择来源平台、课程和截止日期，并在详情调整任务状态。后续采集保留人工修改。

学习通此前提示“该登录跳转尚未适配”时，更新后重新打开官方登录并保存新二维码再扫码。最终包重复安装的数据恢复已验证，旧内部版本号 3→4 直接升级尚未实测；沿用旧版签名支持覆盖安装，保留手机数据时不要先卸载。

二维码过期或官网更新后需重新保存。无法取得图片、未安装 App 或不支持相册识别时，可使用另一台设备扫码，或官网提供的短信验证码等登录方式。MOOC 与 PTA 本版保留官网登录，没有保存二维码按钮。扫码辅助仍需本人官方确认，真实官方 App 的相册识别及真实账号流程尚待真机验证。

图片保存到相册 `Pictures/聚合平台登录`。Android 10+ 通过 MediaStore 保存本应用创建的图片，无需读取相册权限；Android 9 保存时申请存储写入权限，拒绝后仍可改用其他官网方式。扫码确认前保留连接页；离开时尝试清理本应用保存的二维码，强制结束后的遗留图片下次启动重试清理。

手机任务、选课与加密 Cookie 位于应用的私有目录。Cookie 和受保护入口使用 Android Keystore 加密，重启默认复用；官网明确失效时标记过期、引导重新登录并替换当前会话。原生 WebView 的登录环境留在手机应用内。

Windows 与 Android 独立保存数据和登录，不提供跨设备任务合并或 Cookie 传输。更新 APK 时使用同一签名覆盖安装，可保留应用数据；Android **卸载应用或清除应用数据会删除手机记录和密钥**。Windows 卸载的数据保留行为不适用于 Android。

应用在前台时每 30 分钟自动同步已连接平台的已选课程，也可手动同步。后台只按系统调度检查已有提醒，不保证后台采集；省电策略、通知权限和系统调度可能使提醒延迟。

## 重新构建

在项目根目录执行：

```powershell
# 完整桌面构建与发布，再生成对应 Windows 安装包
.\scripts\build.ps1
.\scripts\build-installer.ps1

# 使用已安装的 Android SDK、.NET Android workload 与 JDK 21 构建签名 APK
.\scripts\build-android.ps1 -Version 1.1.2 -VersionCode 4
```

Android 发布密钥及 DPAPI 保护的密码位于本机 `.local/android-signing`，仅构建使用，不随安装包分发。发布更新必须复用同一密钥并增加 VersionCode。手机合成测试入口为 `tests/MobileChecks`，使用独立测试根目录；模拟器原生验证须指定专用测试设备，不能在本人正式手机数据上运行。

构建脚本可用 `-AndroidSdkDirectory` 和 `-JavaSdkDirectory` 指定开发环境。已提交的 launcher 资源来自 `design/icons/app-1024.png`；修改主图标后用 `python scripts/create-android-icons.py` 重新生成（需 Pillow）。`scripts/collect-android-licenses.py` 读取本次构建的 `project.assets.json`，收集 Android 依赖与运行时许可。

`scripts/test-android-installation.ps1` 用于已经建立合成数据基线的专用模拟器，检查同一 APK 的覆盖安装和跨进程恢复；验证通过后按 APK SHA256 更新构建清单，页面目视检查单独记录。首次设备需先运行移动合成检查建立基线，不能把缺少基线解释为升级成功。
